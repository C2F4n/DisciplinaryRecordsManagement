# 机电工程学院自律会违纪记录管理系统

Spring Boot 4.0.9、Java 21、MyBatis、MySQL 8 和 Flyway；前端为 Vue 3、Vite、TypeScript 和 Element Plus。前后端在同一个仓库。默认只监听本机，不需要 Nginx 或 Redis。

目前可用：管理员建立班级和学籍名册；学生核验名册后注册并登录；申请、审批、分配和撤销身份；按本人、班级、部门查看记录；干事登记、修改和删除；部长批量审核、驳回；办公室标记交回或申诉。接口按身份及数据范围授权，写入带版本号，录入请求防重复，关键操作写入 MySQL 审计表。待审核记录按北京时间计算，到期从列表移除并由定时任务标记删除。

已支持月报冻结和下载、正式记录与通报表导出、站内通知、正式记录统计、Excel 名册导入及正式记录保留期管理。

## 待审工作区、系统管理与通报表

- 「违纪记录」可切换全部记录、待审核区和正式记录。各区沿用同一套身份和数据范围。待审核区可使用现有批量审核操作，正式区只包含审核通过后的状态。
- 核心管理员在「系统管理」的「检查项目」「申诉管理」「违纪类型归属」分别维护项目及分类、四个申诉情形和六种违纪类型的部门归属。检查项目支持新增、删除和按分类筛选，默认启用「学院检查 / 学校检查」。申诉名称按需求留空，待学院提供后填写并启用。部门初始归属按需求中的部门分工配置。
- 学生和班委看到的仍是处理状态。办公室可记录具体申诉情形，情形与处理结果必须匹配。直接交回可以留空。检查项目和部门归属更新后，历史记录保留当时的名称和部门。
- 有正式记录导出权限的角色可按当前筛选导出内部通报表，服务器排除待审核、已申诉、已删除及按启用策略到期的记录。通报表可单独配置工作表标题和列顺序，默认沿用正式记录字段。

## 密码与审计

- 左侧「信息说明 → 权限说明」列出各身份的操作范围、已分配账号数和系统上限。多个身份分别计数，同一账号在同一身份下只计一次。停用账号仍计入，已移除名册的学生账号从统计中剔除。
- 「信息说明 → 审批权限」单独列出各身份可批准或驳回的权限申请范围。

- 登录后可在顶部「修改密码」。核心管理员可在左侧「账号注册与权限分配」查到账号后签发 24 小时有效的临时密码，签发时显示一次，使用者登录后须改为自己的密码。重置或修改密码会使原有登录会话失效。
- 「系统管理 → 审计日志」仅核心管理员可访问。可按日期、操作账号、操作和对象过滤，查看状态变更、纠错说明及请求编号。密码和临时密码不写入审计。

## 老师首页与违纪纠错

- 团委老师登录后直接看到统计和最新月报。统计默认展示「已审核」的待处理记录，可切换到全部正式记录；可打开月报明细或下载 Excel，通过「进入记录管理」筛选和修改违纪记录。
- 核心管理员可在未归档记录的「详情 → 纠错」更换绑定学生、改正日期或类型。变更类型时，部门随类型更新。更换学生会按新学籍更新班级和辅导员，撤回原学生的该条业务通知，并通知新学生。
- 「已交回」和「已申诉」可相互纠正，也可恢复为「已审核」。已处理记录更换学生时，恢复为「已审核」并由办公室重新核对。由「已申诉」纠正为「已交回」时，使用纠错时间作为交回时间。
- 纠错需填写原因并校验记录版本。审计表记录状态、学生内部编号、日期、类型及版本的变更。已录入月报的记录禁止用纠错入口改写来源或状态，归档明细和 Excel 可继续下载。

## 名册与导出模板维护

- 左侧「信息登记」可以展开，包含「基础信息写入」「班级信息写入」「信息修改」。「账号注册与权限分配」有独立的侧栏入口。
- 「基础信息写入」用星号标记必填项。学生登记、批量导入和学籍编辑中的手机号可留空。名册里已有手机号时，注册须填入同一个号码。
- 在「班级信息写入」录入辅导员后，添加班级和修改班级共用该名单。每班可选择 1 至 3 名辅导员。下拉选项按拼音排序，可用姓名、全拼或首字母搜索，搜索会忽略空格。已有班级会保留原辅导员。
- 在「基础信息写入」可按姓名或学号删除单个学生，也可以在「班级信息写入」的班级列表点击「清空学生」，确认人数后一次性删除全班名册。删除后无法凭该条学籍注册，已绑定的账号会停止登录。已有违纪记录和月报仍可查询。班级须在学生人数为零时单独删除。
- 核心管理员可在「信息登记 → 信息修改」修改班级名称和辅导员，按班级、姓名或学号查询学生，维护姓名、手机号、所属班级和学籍有效期。变更后历史违纪仍保留录入时的学生、班级和辅导员信息。
- 学生转班时，系统撤销原班委授权。尚未注册的学生使用更新后的名册信息注册。延长学籍有效期可恢复已到期账号的学籍资格，账号还须处于启用状态。
- 新登记与 Excel 批量导入默认要求 12 位数字，例如 `202507101180`。只校验数字和总长度。核心管理员仍可在「信息修改」中调整学号规则，已有学生继续使用原学号。
- 在「系统管理 → 导出模板」上方切换模板，分别设置月报、正式记录和通报表的工作表内标题、列顺序，以及是否显示备注和所属部门。设置保存后用于新导出和新月报，已有月报仍可下载原始文件。
- 名册和模板保存使用版本校验。遇到他人先保存时，系统提示刷新后重试。关键变更写入审计日志，日志只保留操作标识、版本或班级编号及有效期等必要信息。

## 正式记录保留期

- 核心管理员在「系统管理 → 数据保留」查看按周到期的记录数量、暂留数量和清理历史。默认只预览，不删除或隐藏现有正式记录。
- 按违纪发生日期分周，周一至周五为一个业务周。以周五加一年计算到期日，到期当天 00:00 起进入清理范围。启用后，到期的「已交回、已申诉、已录入」不再出现在正式列表、统计和导出中；「已审核」长期保留，待审继续按原规则处理。
- 已交回但还未入月报的记录暂留在库中，冻结后再清理；已主动删除、不再入月报的已交回记录可按期清理。每周可清理的记录在一个事务中删除，记下批次和审计日志。既有月报和 Excel 不会改变。
- 如确认要执行实际清理，在本机 `.env` 中设置 `APP_RETENTION_ENABLED=true` 并重启。默认每日 02:25 检查，每轮最多清理 26 周；可配置 `APP_RETENTION_CRON`、`APP_RETENTION_MAX_WEEKS_PER_RUN` 和 `APP_RETENTION_YEARS`。将定时表达式设为 `-` 可暂停定时删除；关闭总开关也会关闭到期隐藏。Flyway 启动时自动创建清理历史表。

## 正式记录统计和批量名册

- 在「违纪记录」点击「查看统计」。权限和筛选条件沿用记录列表，统计覆盖全部匹配结果，不限当前页，也不计入待审或删除记录。可按日、周、月查看时间分布，并切换类型、状态、部门和班级。自然周从周一开始，趋势最多显示最近 24 段。
- 核心管理员在「信息登记 → 基础信息写入」下载模板。填写已有班级的全名，学号和填写的手机号保持文本，入学日期用 `YYYY-MM-DD`。先校验、按行修正，再确认导入。任何一行失败都不会写入部分名册，也不会覆盖现有学生。
- 「班级信息写入」提供单独的 Excel 模板。每行可录入一个班级及最多三名辅导员。班级名称留空时，只录入辅导员。已登记的同名辅导员会复用。
- 导入后学生可凭名册信息注册。默认每份最多 500 行、文件最大 2 MB，可用 `APP_ROSTER_MAX_ROWS` 和 `APP_ROSTER_MAX_FILE_SIZE` 调整；上传请求大小上限为 `APP_ROSTER_MAX_REQUEST_SIZE`，默认 3 MB。

## 筛选导出和站内通知

- 主席、团委老师、自律管理部部长及核心管理员可在违纪记录页点击「导出正式记录」。Excel 使用已点「查询」的筛选条件，涵盖各页，不含待审核或已删除数据。素拓负责人仍只可下载月报。导出有审计日志；默认每次最多 10000 条，可用 `APP_EXPORT_MAX_ROWS` 调整。
- 学生收到录入、审核通过、交回或申诉通知；录入人收到驳回通知。记录在录入后的次日仍待审时，通知其部门部长；月报生成时如本期还有有效待审记录，则提示自律管理部部长。
- 「通知」页支持查看、已读和全部已读，且每个账号只能读取自己的通知。默认每 5 分钟检查待审提醒，可用 `APP_NOTICE_PENDING_CRON` 调整；设为 `-` 可暂停该定时检查。启动时 Flyway 自动创建通知表和索引。

## 月报规则

- 默认按业务时区在每月 1 日 18:00 起生成上月月报，服务停机错过后会补生成。归期按交回时间，以次月 1 日 00:00 为截止，不按实际生成时间划分。例如 4 月 30 日的记录在 5 月 1 日交回，进 5 月月报；往期遗漏且仍是「已交回」的记录可在后续月份补入。
- 待审核、已审核但未交回、已申诉、已删除的记录不入报。月报生成、保存冻结明细和 Excel、标记「已录入」同一事务提交。之后修改或删除原记录不会影响已生成月报，同一月份也不会重新生成。
- 核心管理员、主席、团委老师、自律管理部部长和素拓中心部长可以看月报、下载 Excel。只有素拓身份的账号不会获得原始记录访问权限。生成和下载都有审计记录。
- 目前 Excel 使用需求中的字段作为通用格式。部署新版时 Flyway 会自动执行 `V2__freeze_monthly_reports.sql`，原有表数据无需手工迁移。

| 月报配置 | 默认值 |
| --- | --- |
| `APP_REPORT_ENABLED` | `true`；设为 `false` 可暂停生成，仍能查阅已归档月报 |
| `APP_REPORT_GENERATION_TIME` | `18:00` |
| `APP_REPORT_POLL_CRON` | `0 * * * * *`，每分钟检查到期月份 |
| `APP_REPORT_MAX_MONTHS_PER_RUN` | 每轮最多补生成 12 期 |

## 后端结构和接口约定

- `controller` 接收 HTTP 请求、校验参数和组装响应，只调用 `service`。权限、业务规则、事务和审计在 `service`；`mapper` 负责 MyBatis 查询和写入。
- `dto` 定义请求和响应字段，`model` 定义角色、记录状态和审计事件。异常类型和错误码在 `exception`，提示语和校验边界在 `constant`。
- JSON API 统一返回 `{"code":1,"msg":"","data":...}`；分页数据为 `{"items":[...],"total":0}`。没有数据的成功操作（包括登录和退出）返回 HTTP 200，`data` 为 `null`。业务错误保留相应的 HTTP 4xx 或 5xx，`code` 为错误码，`msg` 为可展示的提示。MVC 异常与安全过滤器错误使用同一格式，不返回数据库原始错误。

可按环境覆盖 `application.properties` 中的规则，无需改 Java 或重新构建。主要配置如下：

| 环境变量 | 默认值 |
| --- | --- |
| `APP_TIME_ZONE` | `Asia/Shanghai` |
| `APP_PENDING_DAYS` / `APP_EDIT_DAYS` | 待审 4 个自然日、干事编辑 2 个自然日，均含当天 |
| `APP_ENROLLMENT_YEARS` | 学籍有效期 4 年 |
| `APP_PENDING_CLEANUP_DELAY` | `PT30M`（ISO 8601 时长） |
| `APP_DEFAULT_DISPOSITION` | 院内通报批评，提交书面理论学习 |
| `APP_LOGIN_WINDOW` / `APP_LOGIN_ATTEMPTS_PER_IP` | 每来源 IP 每 `PT1M` 最多 60 次登录或绑定请求 |

## 连接新数据库

用 MySQL 管理账号创建空库和程序账号。替换示例密码，已有空库时可直接为程序账号授权。

```sql
CREATE DATABASE disciplinary_records CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'discipline_app'@'127.0.0.1' IDENTIFIED BY '替换为随机数据库密码';
GRANT ALL PRIVILEGES ON disciplinary_records.* TO 'discipline_app'@'127.0.0.1';
```

把仓库根目录的 `.env.example` 复制为 `.env`（部署包直接编辑自带的 `.env`）。模板里只有第 1、2 段需要填，其余留空即用程序默认值。库名和数据库账号可自定义，保持 SQL 与 `.env` 的配置一致。

```dotenv
DB_URL=jdbc:mysql://127.0.0.1:3306/disciplinary_records?connectionTimeZone=Asia/Shanghai
DB_USER=discipline_app
DB_PASSWORD=你的数据库密码
APP_ADMIN_USERNAME=admin
APP_ADMIN_PASSWORD=你的网页管理员初始密码
```

从 `.env` 所在目录启动时会读取这些配置。首次连接空库，Flyway 自动建表并写入基础配置。系统根据 `APP_ADMIN_*` 创建网页管理员。部署包可双击「启动系统.cmd」。完整步骤与常见问题见 [部署教程](./deploy/部署教程.md)。

`.env` 按 properties 语法解析：值一律用 ASCII、不加引号，中文只能写在注释里。`APP_ADMIN_PASSWORD` 不合规时，空库首启会直接退出（日志提示「密码须为 6–18 个字符」）。`DB_URL` 末尾的 `connectionTimeZone` 不要删，否则日期会随时区偏移。

## 本地开发运行

开发环境使用 Java 21、Node.js 22.12+ 或 24 和 MySQL 8。

也可以用 PowerShell 配环境变量启动。默认连接本机 3306 端口，Flyway 会创建业务表。`.env` 默认开启本机 HTTPS，访问地址为 <https://127.0.0.1:18643>；若把 `server.ssl.enabled` 设为 `false`，则改为 <http://127.0.0.1:18643>，同时须把 `SESSION_COOKIE_SECURE` 也设为 `false`。

```powershell
$env:DB_USER = 'discipline_app'
$env:DB_PASSWORD = '你的数据库密码'
$env:APP_ADMIN_USERNAME = '你的管理员登录名'
$env:APP_ADMIN_PASSWORD = '你的管理员密码'
.\mvnw.cmd spring-boot:run
```

已有 Maven 时，也可以用 `mvn.cmd spring-boot:run`。首次启动会创建唯一的核心管理员。登录名须以小写字母开头，至少 4 个字符。正式密码为 6–18 个字符，至少包含一个英文字母和一个数字，只允许英文字母、数字、`_` 和 `@`，区分大小写。仅监听本机时，六位纯数字初始密码按 24 小时有效的临时密码处理，登录后须改密。创建完成后可清除 `APP_ADMIN_*` 环境变量，重启会使用数据库中当前的密码。Vue 开发代理默认转发到 18643；如果通过 `APP_PORT` 改了后端端口，再用 `API_PROXY_TARGET` 指向新地址。

新开一个终端启动前端：

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

打开终端打印的本地地址（通常是 http://127.0.0.1:5173）。核心管理员登录后，在「班级信息写入」添加班级，再到「基础信息写入」登记学生。学生在登录页选「首次使用？注册学生账号」，填写名册中的学号、姓名和班级，并设置密码。名册已有手机号时也须核对，学籍须有效且未注册。注册时须填写通知邮箱，点击「发送验证码」。名册核对通过后，输入邮件中的 6 位验证码即可继续注册。验证码 10 分钟内有效，每个学号间隔 60 秒可重发，最多允许尝试 5 次。注册后默认拥有学生权限，已有账号可在「通知 → 通知邮箱」补填或修改。

学生在「权限申请」提交申请并查看结果。核心管理员可审批所有开放申请的身份，主席和团委老师可审批班委及部门干事，部门部长可审批本部门干事。团委老师身份由核心管理员直接分配。符合审批范围的账号会收到站内通知，可在「请求待处理」批准或驳回。系统保存申请时间、身份及范围、审批人、审批时间和处理意见。

## 注册验证码和违纪邮件

- 注册验证码和违纪提醒共用 SMTP 发件地址与授权码。SMTP 配置好并重启后，学生才能验证邮箱并注册。已有账号照常登录。
- 新登记违纪时照常产生站内通知。启用邮件后，系统会将有邮箱的学生对应的新增通知加入数据库队列，在后台发送。邮件只提示登录查看通知，违纪详情通过工作台查看。邮件功能启用后处理新登记，已有记录无需补发。
- 用核心管理员登录，在「系统管理 → SMTP 配置」输入独立配置密码。初始密码为 `a018779`，可在同一页的「修改配置密码」中更换。解锁有效期为 10 分钟，离开页面或锁定后再次查看须重新解锁。
- 按下表填写，点「保存 SMTP 配置」并重启服务。勾选「启用违纪邮件通知」可给新登记的违纪发邮件。注册验证码使用同一发件设置。页面首次保存前沿用 `.env` 配置，保存后优先使用数据库中的设置。
- 页面录入的授权码以密文存入数据库。服务自动生成独立的 `.smtp-settings.key`，也可用 `SMTP_SETTINGS_KEY_FILE` 指定密钥文件路径。迁移服务时须保留该文件；若文件丢失，可在页面重新录入授权码。
- 邮件发送失败间隔 5 分钟重试，总计最多 5 次。邮件失败不影响违纪登记和站内通知。发送状态在 `notification_email` 表中记录。

| 界面字段 | 填写内容 |
| --- | --- |
| SMTP 服务器 | 邮箱服务商提供的服务器地址，例如 `smtp.example.com` |
| 端口和连接加密 | 按服务商给的组合选择，常见为 587 + STARTTLS 或 465 + SSL/TLS |
| 发件邮箱 | 发送邮件时显示的邮箱地址 |
| 使用 SMTP 身份认证 | 普通邮箱发信时开启 |
| SMTP 登录账号 | 通常填写完整的发件邮箱地址 |
| SMTP 授权码 | 服务商提供的 SMTP 授权码或应用专用密码。页面显示已配置时，留空保留现有授权码 |

## 验证与打包

- `mvnw.cmd test` 默认使用内存测试库，覆盖名册核验注册、权限申请及审批、密码重置、审计查询、并发审核、名册维护、业务选项、通报表、导出模板、月报冻结与下载和按周清理。要验证 MySQL，提供 `TEST_DB_URL`、`TEST_DB_USER` 和 `TEST_DB_PASSWORD`，指向一个新建的独立测试库。
- 前端目录运行 `npm.cmd run build`，完成 TypeScript 检查和生产构建。
- **一条命令出交付包**：`.\打包.ps1`。产物在 `dist\违纪统计系统_<时间戳>`，只包含 JAR、`.https`、`启动系统.cmd`、`.env`、`.env.example`、`包信息.txt` 和两份说明文档；证书与 keystore 口令每次重新生成并直接写进该目录的 `.env`，`包信息.txt` 记录构建时间和 JAR 的 SHA-256 供收包方核对，不会把开发机的 `.env`、日志、`.smtp-settings.key` 带出去。加 `-WithTests` 先跑测试，加 `-ForceFrontendBuild` 强制重建前端。
- 手工打包：先构建前端，再在根目录运行 `mvnw.cmd clean package`。Maven 会把 `frontend/dist` 放进 Jar。保留上面的数据库环境变量，运行 `java -jar target/DisciplinaryRecordsManagement-0.0.1-SNAPSHOT.jar` 即可由 Spring Boot 同时提供页面和 API。
- **代码风格**：`mvn spotless:apply` 统一 import 顺序并删除无用 import，`mvn spotless:check` 做校验；缩进与换行由 `.editorconfig` 约定。项目不使用通配符 import。
- 正式部署前使用 HTTPS（学院网关或 Spring Boot 证书皆可），设置 `SESSION_COOKIE_SECURE=true`，限制数据库访问来源，并核对数据保留和备份恢复策略。不要把测试数据混进正式库。
